# MusicDL Implementation Plan

> **For agentic workers:** Execute this plan task by task using the executing-plans skill. The user's supplied specification is the implementation authority.

**Goal:** Build and install a working terminal downloader with safe universal input and an independent library.

**Architecture:** Typed provider adapters feed individual tracks into a durable queue. An async engine and audio processor are shared by the CLI and Ink dashboard. SQLite owns recovery, indexing and ordered playlists.

**Tech Stack:** Strict TypeScript, Node >=24.12, pnpm, Ink, Clack, Vitest, SQLite, yt-dlp, spotDL, FFmpeg.

**Spec:** ../../design.md and the user's full project specification.

## Global Constraints

- Never silently expand a video to its playlist; --single and --playlist explicitly override.
- MP3 defaults to LAME VBR -q:a 2 and ID3v2.3; FLAC requires an actual lossless source.
- No shell execution, traversal, credential logging, unapproved library mutation or overwrite.
- Defaults: ~/Music/MusicDL/Downloads and ~/Music/MusicDL/Library.
- No commit, publication or modification of the existing Canary library is necessary.

## Review Focus

- Playlist entries that are unavailable must be reported and never become guessed URLs.
- Duplicate selected tracks must not race into multiple downloads or overwrite files.
- A crash after file publication must recover without redownloading or losing history.
- Cancelled child processes must stop writing before staging is removed.
- M3U inputs and metadata with terminal control characters must not become commands or escape destinations.
